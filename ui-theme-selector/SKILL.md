# UI Theme Selector

你的工作不是直接套一個「好看」的流行風格，而是根據專案本身的語境，推導出**合理、可信、耐看、可延展**的 UI/UX 主題，並避免產生過強的 AI 生成感。

## 核心目標

在任何 UI 任務中，先回答這個問題：

**這個產品如果是由一個成熟、了解使用者的團隊設計出來，它應該長什麼樣子，而不是像一個 AI 預設模板？**

你要優先追求：

1. 與產品定位一致
2. 與使用場景一致
3. 與目標受眾一致
4. 與品牌語氣一致
5. 長時間使用仍然舒服
6. 實作與維護成本合理
7. 不落入常見 AI 審美套路

---

## 何時啟用這個 skill

當你發現任務包含以下內容時，應主動使用本 skill：

- 建立新頁面或新產品介面
- 重設網站或 app 的視覺方向
- 決定 dashboard、marketing site、landing page、CMS、SaaS、工具型產品、內容型產品的主題
- 選擇顏色、字體、圓角、陰影、密度、留白、插畫、圖示風格
- 實作 design system 或共用 UI primitives
- 使用者要求「不要太像 AI 做的」
- 使用者要求「更像真實產品」「更像有品牌感」「更有 domain 味道」
- 你發現目前畫面有明顯模板感、玻璃擬態濫用、過亮漸層、過多發光、誇張圓角或展示型設計大於可用性

---

## 先做判斷，再做設計

在開始寫 UI 之前，先從專案中萃取以下訊號。

### 1. 產品類型

判斷它比較接近哪一類：

- B2B SaaS
- 內部工具 / admin
- 金流 / 法務 / 醫療 / 高信任產品
- 創作者工具
- 開發者工具
- 教育產品
- 內容媒體
- 電商品牌
- 社群產品
- AI native product
- 遊戲 / 娛樂 / 活動型網站
- 個人品牌 / 作品集

### 2. 主要使用者心態

判斷使用者進入產品時更在意什麼：

- 效率
- 信任
- 清楚
- 掌控感
- 探索感
- 成就感
- 靈感
- 安心
- 專業
- 降低學習成本

### 3. 使用情境

判斷產品主要是：

- 長時間停留使用
- 快速完成任務
- 高頻重複操作
- 行銷導向瀏覽
- 內容閱讀
- 資料掃描
- 決策支援
- 手機優先
- 桌面優先

### 4. 品牌語氣

從 README、產品文案、首頁 copy、命名與功能結構推斷品牌更像：

- 穩健專業
- 溫暖可信
- 極簡理性
- 創新前衛
- 友善輕量
- 高端精緻
- 技術導向
- 年輕活潑

### 5. 領域視覺慣性

理解這個領域有哪些使用者已經熟悉的視覺語言，哪些該延續，哪些可以刷新，但不要為了「與眾不同」而犧牲辨識性。

---

## 主題選擇規則

根據前述訊號，在以下方向中挑選**最適合的一種主題基底**，必要時可少量混合，但不要做成拼貼。

### A. Quiet Professional

適用：

- B2B SaaS
- 金流、法務、醫療、企業服務
- 後台、分析平台、資料密集產品

特徵：

- 中性配色
- 低飽和重點色
- 較小圓角
- 弱陰影
- 清楚層級
- 高可讀性
- 少裝飾

避免：

- 玻璃擬態
- 螢光漸層
- 大面積發光
- 過度 hero 化區塊

### B. Warm Editorial

適用：

- 教育、內容、顧問、生活風格、品牌故事型產品

特徵：

- 較柔和底色
- 良好排版節奏
- 可用 serif 或具性格的字體搭配 sans
- 強調閱讀、留白、節奏
- 圖像與內容優先

避免：

- 過度卡片化
- 所有東西都像 dashboard
- 過度功能感

### C. Precise Technical

適用：

- 開發者工具
- infra / API / security / observability
- 需要專業與系統感的產品

特徵：

- 清晰網格
- 有節制的密度
- 偏功能型元件
- 可接受較冷靜的色彩
- 用字直接
- 視覺偏系統化與工程感

避免：

- 炫技動畫
- 太多 marketing 式裝飾
- 把工程產品做成潮流海報

### D. Friendly Utility

適用：

- SMB 工具
- 一般工作型 app
- 協作工具
- onboarding 與流程型產品

特徵：

- 親和但不幼稚
- 元件乾淨
- 表單與任務流程清楚
- 導引感強
- 容錯設計佳

避免：

- 太冷
- 太硬
- 太像 enterprise 模板

### E. Premium Minimal

適用：

- 高單價品牌
- 作品集
- 設計導向產品
- 高端 DTC

特徵：

- 克制
- 強留白
- 排版主導
- 細節精準
- 色彩少但質感高

避免：

- 流行 UI 特效堆疊
- 過量功能模塊
- 為了高級而降低可讀性

### F. Expressive Modern

適用：

- 創作者產品
- 年輕品牌
- 活動頁
- 部分 AI-native 消費型產品

特徵：

- 可以使用較鮮明 accent
- 視覺節奏更大
- 可加入少量動態與視覺記憶點
- 但仍需有品牌邏輯

避免：

- 把「未來感」誤當成產品感
- 大量紫藍漸層、玻璃、光暈、漂浮球、星空背景
- 一看就像 AI demo landing page

---

## 明確避免的「AI 感」特徵

除非專案明確要求，否則避免以下常見模式：

- 紫色、藍色、青色的預設 AI 漸層到處都是
- 過量玻璃擬態、背景模糊、霓虹 glow
- 誇張大圓角，所有元件都像泡泡卡片
- 每一區都像獨立 demo section，缺乏真正資訊架構
- hero 很炫，但主要任務流程很弱
- dashboard 中每張卡都同權重、同視覺節奏
- 過多徽章、閃光點、星星 icon、magic wand 隱喻
- 插畫與裝飾過多，卻沒有幫助理解
- 所有內容都過度置中，像展示頁而不是可用產品
- 文案過度空泛：smart, seamless, intelligent, next-gen, powerful
- 空狀態與 loading 畫面太用力，主要工作畫面反而普通
- 為了「設計感」犧牲密度、可掃描性與操作效率

如果目前 UI 有這些特徵，優先做**去模板化、去浮誇化、去展示化**處理。

## 預設設計決策準則

### 色彩

- 先決定 1 個主色、1 個 accent、1 套中性色，不要先做彩虹盤
- 高信任產品降低飽和度
- 工具型產品優先考慮對比、狀態色與資料可讀性
- 品牌色應服務資訊層級，不是主導全部畫面

### 圓角

- 預設從中小圓角開始
- enterprise / data-heavy / technical 產品使用更克制的圓角
- 年輕或友善品牌才提高圓角，但也不要所有層級都一樣圓

### 陰影

- 預設弱陰影或幾乎不用
- 優先用邊框、底色差、間距建立層次
- 不要用濫量陰影假裝高級

### 字體

- 從系統字體或成熟、可讀性高的 sans 開始
- serif 只在 editorial、premium、品牌敘事強的情境使用
- 不要用字體硬做風格，先確保內容層級與閱讀性

### 密度

- 工具型產品比展示型頁面更需要合理密度
- 不要為了「呼吸感」讓使用者一直捲動
- 空間要有節奏，而不是單純把所有 padding 放大

### 圖示與插畫

- 優先一致、低存在感、功能導向
- 除非品牌真的需要，避免到處放 3D icon、AI 插畫、抽象 blob

### 動效

- 用於回饋、導引、狀態轉換
- 不要把動效當作彌補結構薄弱的方法

---

## 產出格式要求

每次執行這個 skill，先在心中完成判斷，再在實作中體現。若需要向使用者說明，請用以下簡潔結構輸出：

1. **推薦主題方向**
   - 用一句話命名，例如：Quiet Professional with Warm Data Accents

2. **選擇理由**
   - 依產品類型、使用者心態、品牌語氣、使用情境說明 3 到 5 點

3. **具體視覺規則**
   - 色彩
   - 字體
   - 圓角
   - 邊框 / 陰影
   - 間距密度
   - 元件語氣
   - 插圖 / 圖示策略

4. **應避免的設計**
   - 列出會讓畫面產生 AI 感的特徵

5. **實作優先順序**
   - 先改 layout 與 hierarchy
   - 再改 tokens
   - 再改 components
   - 最後才做裝飾與動效

---

## 實作行為守則

當你開始修改介面程式碼時，遵守以下原則：

- 先從 layout、spacing、hierarchy、type scale 下手，再碰特效
- 優先建立少量可重用 design tokens，不要寫滿頁面級 magic numbers
- 優先修正資訊架構，而不是只換色
- 同一頁面中要有明確的主次節奏，不要所有卡片一樣亮
- 真正重要的 CTA 應少而清楚
- 表單、表格、列表、狀態訊息的可用性比 hero 更重要
- 若已有品牌資產，優先延續，而不是推翻重做
- 若專案已存在某種風格，應做收斂與提純，不要無端改成另一個宇宙
- 若需求模糊，預設選擇耐用、克制、可持續擴展的方向

## 專案類型對應的快速預設

### B2B dashboard

預設：

- Quiet Professional
- 中性灰階 + 單一低飽和品牌色
- 小到中圓角
- 清楚表格、篩選器、狀態標籤
  避免：
- 漂浮玻璃卡
- 大 hero
- 過多裝飾 icon

### AI 工具但要避免 AI 感

預設：

- Friendly Utility 或 Precise Technical
- 把「可信的工作介面」放在「未來感」前面
- 讓 AI 是功能，不是裝飾語言
  避免：
- 紫藍漸層氾濫
- 魔法棒隱喻
- 星塵、光暈、orbit 圖形

### 金流 / 醫療 / 法務

預設：

- Quiet Professional
- 更高對比、更少裝飾、更穩定節奏
  避免：
- playful 過頭
- 太多插圖
- 情緒化色彩

### 教育 / 內容平台

預設：

- Warm Editorial 或 Friendly Utility
- 讓排版、閱讀與導覽成為主角
  避免：
- 把內容站做成 SaaS 後台

### 設計品牌 / 作品集

預設：

- Premium Minimal
- 精準排版、節制元件、強留白
  避免：
- 為了高級而不可用
- 充滿流行 UI 特效

---

## 衝突時的優先順序

當「好看」與「合理」衝突時，選合理。
當「品牌感」與「可用性」衝突時，先保可用性，再微調品牌感。
當「炫」與「可信」衝突時，依產品類型決定；大多數工具型產品優先可信。
當你不確定時，請選擇更克制、更真實、更像成熟產品團隊會做出的版本。

---

## Definition of Done

只有在以下條件大致滿足時，才算完成：

- 主題方向能被清楚命名
- UI 風格與產品定位一致
- 畫面不再依賴 AI 模板感的視覺套路
- 關鍵頁面層級更清楚
- 元件風格一致
- 色彩、圓角、陰影、密度有系統
- 至少能指出 3 個原本的 AI 感來源，並已被消除或弱化
- 最終結果看起來像「真實產品」，不是「生成式展示稿」
